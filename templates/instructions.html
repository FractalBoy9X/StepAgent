{% translate "Lifecycle and status" %}

{% translate "Lifecycle is the phase an interaction reached: started, streaming (arriving in pieces), waiting (for your decision), completed, failed, cancelled, or aborted. {% translate "Details" %}

{% translate "Select a step, matrix cell, table row, or relation to inspect it. The details band above the chart lists the step's key fields on the left, and beside them three collapsible layers — the same data at three depths:" %}

{% translate "Content" %}{% translate "A decoded, human-readable view of the step, adapted to its type: commands show the command line with exit code and output, patches show a colored diff per file, tool calls show their arguments and unwrapped result, token counters show a number grid. Open by default — this answers most questions." %}
{% translate "Normalized interaction" %}{% translate "What the parser derived from the log: correlation identifiers, results, and metadata. Fields already listed at the top of the panel are omitted here to avoid repetition; the complete JSON is one click away under Full JSON." %}
{% translate "Source records" %}{% translate "The exact JSONL lines of the original log file this step was built from — one card per line, with the envelope type, subtype, position, and timestamp in the card header and the untouched record underneath." %}

{% translate "The data flows one way: log lines → parser → normalized interaction → step on the chart. Long previews are cut with an explicit notice and a button that reveals everything — nothing is truncated silently. Each JSON layer has a copy button. Press Escape to clear the selection." %}

{% translate "Below the step title a bar navigates to the previous and next step. Files a step touched are listed as clickable resources inside its Content layer, next to what the step did. The remaining relations are only the causal ones, grouped by verb, each pointing at a step number — turn and agent membership live in the field list instead." %}

{% translate "How the Content layer is built" %}

{% translate "Whatever the step type, the Content layer always uses the same sections in the same order: What, Where, Input, Result, Status, Timing, Provenance. Every value is read from the original log line first and from the parser's summary only as a fallback, so nothing depends on the shortened description." %}
